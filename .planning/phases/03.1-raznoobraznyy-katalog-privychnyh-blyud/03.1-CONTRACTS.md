## Разделение файлов

- `data/sources/phase031.snapshot.json` содержит новые исходные nutrient rows, label excerpts, observations/estimates, safety identity evidence и hash. Данные делятся на записи по profileId.
- `src/data/familiarRecipes.ts` содержит30 оригинальных Recipe объектов и стабильные exports по группам матрицы.
- `src/data/catalogExpansion.ts` преобразует source-specific данные в FoodProfile, проверяет source manifest и собирает семейства выпусков. Это короткая сборка и валидатор с функциями по виду источника.
- `src/data/catalog.ts` сохраняет историческую сборку и её прежнюю проверку, экспортирует historical release, current bundledCatalog/port и список source-approved release ports. Исторический comparator проверяет исходный снимок.
- `src/data/recipeDiversity.ts` — compiled metadata по release version и recipeId. Группы `poultry`, `fish`, `meat`, `egg`, `dairy`, `legume`, `plant`, отдельный family. Обязательная группа определяется фактическими ингредиентами и способом приготовления. Несколько тегов возможны. Sidecar не входит в persisted Recipe.

## Выпуски и сохранение

Исторический `mealplan-2026-10-28-1` остаётся исходным52/12 снимком. План01 выпускает `mealplan-2026-11-11-1` с56 рецептами, план02 — `mealplan-2026-11-11-2` с68, план03 — `mealplan-2026-11-11-3` с75, план04 — `mealplan-2026-11-11-4` с82. Каждый срез immutable. Новые записи добавляются, принятые записи прежнего среза сохраняют значения. Release-spec фиксирует точные profileId/recipeId наборы. Compiled registry поддерживает все выданные срезы, поэтому меню, созданное между задачами, восстанавливается после продолжения. Это обратимое решение разработчика о безопасной поэтапной поставке.

`bundledCatalog` и `bundledCatalogPort` всегда указывают последний source-approved release. `sourceApprovedCatalogPorts` — readonly map по version. `createVersionedGeneration(ports, options?)` возвращает GenerationPort, выбирает compiled port по `request.inputs.catalogVersion`, затем передаёт запрос существующему `createLocalGeneration`. Unknown version даёт GENERATION_DATA_INCOMPLETE с UNSUPPORTED_CATALOG_VERSION. Полная sameSnapshot-проверка остаётся внутри createLocalGeneration. App использует versioned generation по умолчанию. Инъекция тестового GenerationPort сохраняет прежний контракт.

Storage key `mealplan:guest:active-plan:v1`, schema1, лимит4млнbytes и ceilings сохраняются. Trusted registry получает только compiled snapshots. Новое планирование использует current. Append/recreate старого набора использует его сохранённые inputs/catalog/pantry/dates/settings. Оболочка содержит одну версию. Выбор нового планирования остаётся существующим пользовательским действием.

## Manifest и единицы

Для каждой записи обязательны productId/profileId, identity/state, edible reference, nutrient source kind, дословные исходные значения, location/recordId/hash и mapping rationale. USDA даёт19выбранных записей исследования, творог5% берётся из label117/16.5/5/1.5 на100г. Извлечение `.tmp/phase031-food-probe.json` переносится в tracked evidence. Если tmp отсутствует, восстановить извлечение из закреплённого USDA ZIP. Лицензия USDA CC0 относится к USDA. Для label сохраняется короткий числовой excerpt и attribution.

У цены сохраняются `estimate: true`, chosen amount/RUB/reference, observed amount/unit/date/scope, targetScope Санкт-Петербург, assessmentDate, source reference, derivation и assumptions. Разрешены документированные representative estimates. Неудачный сетевой запрос записывается как неуспешный, следующий источник либо имеющийся обоснованный ориентир используется для завершения записи. Наблюдение609RUB/kg куриного филе и выбранная оценка имеют разные поля.

Яйца — масса без скорлупы, молоко/масло — взвешенная масса, мясо/рыба — мякоть без костей, рыба без глазури после размораживания, крупы/чечевица/макароны — сухие, нут/фасоль — готовые drained. Сухие и консервированные бобовые имеют разные productId. Яйцо сохраняет прежние pcs и получает g/kg. Pantry pcs, ml или неизвестное количество остаются с существующей диагностикой, пока конкретный profile conversion не подтверждён. Равенство мл и г не вводится. В рецепте учтён весь поданный соус/масло. Технологическая вода указана в шагах. Расчёт основан на съедобных входах, оценка приготовленного выхода и retention не заявляется.

## Поиск и независимые проверки

Первый tracer проходит полный compiled current catalog, fixed B1/L1/D7/S1 через buildActivePlanEnvelope/projectPlan/real save/load/UI. Дополнительный сценарий первого плана проходит обычную кнопку создания меню через App, реальный GenerationPort и текущий каталог. Fixed tracer и обычный generation имеют отдельные assertions. Ожидаемые литералы готовятся независимой Decimal-арифметикой из закреплённых source rows. При неизменённых составах на человека1421.72ккал/86.767Б/40.709Ж/180.033У. Ценовые литералы закрепляются после выбранных estimate rows, expected не вызывает production projector.

Diverse starts состоят из cheapest fallback и seed-rotated полных balanced assignments по admitted candidates. Каждый start/replacement занимает прежний transition/evaluation/deadline budget. Hard admission и final purchase budget сохраняются. Family coverage применяется к доступным группам. Synthetic catalogs без sidecar сохраняют ID-based поведение. Historical version использует историческую search policy для прежних deterministic outputs. Новые выпуски используют diverse policy.

Acceptance policy разработчика — семь seeds11/23/37/53/71/89/107,2человека/7дней/30мин/6000RUB, variety medium/max. Для каждого successful seed проверить птицу, рыбу, мясо, бобовые, яйцо либо молочку и минимум5 новых recipeId. До фиксации assert доказать существование подходящего assignment независимой суммой source prices. При недостаточности6000 изменить только явно названный test fixture budget до проверяемого значения и записать причину. Default3000 и пользовательские настройки сохраняются. Default должен дать допустимый mixed результат хотя бы с2новыми группами при полном источнике данных. Если фактические оценки делают этот порог математически недостижимым, сохранить доказательство и проверить существующее честное объяснение, без ослабления budget. Min variety допускает повторы и выбирает смешанный feasible start. Medium/max не штрафуют группы, запрещённые настройками.

Scoped `--ids` применяется при незавершённых партиях.

Генерация инструментом ImageGen по одному блюду с сохранением original raster и фактического invocation. Читаются imagegen skill и предыдущие ledger patterns. Провайдер, prompt, дата, artifact, условия, hash, размеры, visual-review фиксируются по факту. Стиль реалистичной домашней еды,4:3. Карточка показывает весь согласованный гарнир и соус. Каждый raster просмотрен рядом с составом. Batch10 является набором отдельных generation calls, завершение сохраняется по каждому изображению. Retry выполняется после восстановления инструмента. Платные ключи и API для обхода ограничения исключены из scope.

## Размер задач

Первый tracer пересекает source→catalog→trust→storage→React и требует более5путей. Пакеты медиа содержат десять отдельных бинарных assets. Эти две группы выделены как связные вертикальные задачи с бюджетом ниже smart zone. Искусственное слияние исходных данных и кода ухудшило бы читаемость. Остальные code tasks ограничены5файлами. Это решение декомпозиции согласовано с родительским orchestrator, scope30 сохраняется.
