Контракт первого действительного плана и рассчитанных покупок; это требования к будущей реализации, а не отчёт об её выполнении. Решения CONTEXT приняты агентом в разрешённом auto-режиме; новые обратимые UI-детали ниже — auto-defaults, а не ответы человека.

Наследуются `01-UI-SPEC.md`, `src/shared/styles/tokens.css`, `src/shared/ui.tsx`, `ProductCombobox.tsx`, названия вариантов из `features/wizard/copy.ts`, подтверждённые UAT H1–H9 и поправка C1. Примерные суммы/даты/КБЖУ с картинок не являются данными каталога.

Граница: APP-04, WIZ-08, DATA-01/02/03, CALC-01/03/04/05/06/07, GEN-01…05, MENU-01/04, SHOP-01/04. ## Layout and Interaction Contract

### Общие экраны и доступность

360/390/430: одна колонка, gutter 16px. 768–1199: gutter 24px, существующий main max-width 640px; 1199 ещё bottom nav. ≥1200: sidebar 240px, main max-width 960px/gutter 32px. Мастер и генерация fullscreen без nav, max-width 640px на всех ширинах. Phase 2 menu — последовательные дневные секции на всех ширинах; недельная сетка/табы относятся к Phase 3, не пытаться вместить семь узких колонок.

Каждая цель ≥44×44px, отдельные цели с gap ≥8px; primary на mobile full-width/min-height 48px. Wizard footer sticky, с фактической измеряемой высотой, safe-area и резервом +16px. Сохранить исправления Phase 1: перенос длинных choice labels, наглядная точная сумма бюджета, единые review labels и динамическое измерение footer/nav. Новые ссылки menu→shopping в Phase 2 в потоке; закреплённый shopping CTA назначен MENU-05/Phase 7. Не накладывать второй fixed footer на bottom nav.

DOM-порядок = визуальный; native button для действий, Link для переходов, details/summary для источников и запасов. Route change фокусирует h1; ошибка формы — первое неверное поле и видимую связанную ошибку. Tab/Shift+Tab/Enter/Space работают без мыши; новые навигационные переходы не заменять div-onClick. При cancel фокус возвращается инициатору, при его отсутствии — h1 исходного экрана. Ошибку операции объявить один раз, status — в одном polite live region; фоновые строки не крадут фокус.

Sticky элементы не закрывают целиком ни поле, ни его ошибку, ни focus-ring: scroll-padding/scroll-margin учитывают реальные высоты. При открытой клавиатуре/малой высоте или 200% zoom footer переходит в поток, если иначе перекрывает ввод. Сохранить Safari 15 fallback/100vh, safe-area и existing ConfirmDialog с trap/Escape/возвратом фокуса; не требовать inert/dvh. Не отключать zoom, не маскировать overflow страницы. Любой текст переносится, grid/flex children min-width:0, длинный ID/название overflow-wrap:anywhere; суммы не режутся ellipsis. Motion 120ms color/opacity, reduced-motion убирает анимацию.

### Запуск, применение и сохранение

| Decision | Predicate / состояние | Обязательный UI и переход |
|----------|----------------------|---------------------------|
| D-01 | Валидный финальный шаг | «Составить меню» заменяет «Проверить настройки»; валидирует все четыре шага, создаёт immutable applied snapshot и начинает реальную операцию; до запуска draft не называется applied |
| D-02 | «Меню за 1 клик» | Вторичный welcome CTA; последние валидные applied имеют приоритет; иначе валидный текущий draft/defaults Phase 1. При невалидном draft открыть первый ошибочный шаг, не чинить молча; показать базу запуска по строке Copywriting |
| D-03 | Шаг 3 / 4 «Пропустить» | Secondary: шаг 3 → шаг 4; шаг 4 → общая валидация и генерация. Рядом явно объяснить сохранение уже введённого. Partial/невалидные строки не обходят валидацию; очистить можно только отдельным existing действием |
| D-01/18 | Draft отличается от active snapshot | В мастере «Редактируются настройки следующего меню»; сводки старого menu/shopping берутся только из его applied snapshot, а не draft. Сохранение черновика не означает применение меню |
| D-16 | Pending current request | `/plan/generating`, h1 «Составляем меню», indeterminate indicator без выдуманных процентов; 4 строки Copywriting по кругу ~2s только pending, кнопка «Отмена»; повторный submit заблокирован |
| D-16 | Cancel / 30s / navigation away | Отменить текущий request; поздний resolve/write не меняет applied/active/route. Cancel возвращает исходный экран с draft/старым планом; timeout показывает error actions. Быстрый успех сразу завершает pending |
| D-07/10/15 | Нет допустимого результата | Показать конкретную проверяемую причину и error controls ниже; не рисовать частичный план как допустимый, не снимать ограничения и не объявлять отсутствие данных безопасностью |
| D-18 | Valid result + successful save | Атомарно применить целый active snapshot, затем `/menu`; applied/даты/seed/catalogVersion/instance IDs/pantry snapshot сохранены вместе. Только реальный save даёт «Меню сохранено на этом устройстве» |
| D-18 | Result valid, save failed | Остаётся экран результата операции с явным memory-only candidate и retry-save; прежний active/persisted план не заменять. Не объявлять успех генерации как успешное сохранение и не перезапускать поиск при retry-save |
| D-18 | Active load pending / corrupt / error | Skeleton menu/shopping или state ошибки; corrupted snapshot не перезаписывать автосохранением. «Повторить загрузку» и «К настройкам»; отсутствие валидного producer не равно наличию плана |

Сравнение вариантов/пересборка с сохранением истории в Phase 3; здесь один действительный активный план. Старый active сохраняется при любой генерационной ошибке/отмене/ошибке записи. «+ Новое меню» открывает существующий мастер без предварительного удаления active; если позднее добавляется явное уничтожение плана — необходим отдельный ConfirmDialog, оно не является действием Phase 2.

### Базовый menu и показатели

| Decision | Predicate / данные | Представление |
|----------|-------------------|---------------|
| D-05/19 | Есть active plan | h1 «Меню на неделю» для 7 дней, иначе «Меню на N дней» с правильной формой; даты начала/конца и «На N человек». Период 1–7 дней начинается с локального календарного сегодня при запуске; хранить date-only basis без UTC-сдвига. Отдельные секции сохранённых дат, сегодня подписано только при совпадении |
| D-05/09 | День и recipe instances | Четыре именованных слота в порядке «Завтрак», «Обед», «Ужин», «Перекус»; текст названия реального рецепта, время, число порций семьи, КБЖУ/оценочная цена на порцию. У каждого instance устойчивый day/slot ID; статическая строка без ложного tap/⋯/замены/рецепт-ссылки |
| D-04/17 | Денежная сводка | Три подписанные суммы: «Все ингредиенты», «Покрыто запасами», «Нужно купить». Крупное «Покупки: ≈ {purchase} / {limit} ₽»; «Лимит дополнительных покупок для всей семьи на {days}» и «Осталось {remainder} ₽». Форматтер не дублирует ₽ при подстановке |
| D-04/15 | Budget indicator | Значение = purchases/limit, сопровождается текстом; нулевые purchases дают 0%, равенство лимиту — 100%/«Осталось 0 ₽». Hard decision по полной точности. При несовместимом/превышающем лимит saved snapshot показать ошибку валидации и восстановление, не выдавать его за допустимый новый план |
| D-05/06 | Nutrition normal | «Среднее на человека в день» по фактическим дням; под каждым днём «На человека за день»: ккал целые, Б/Ж/У по 1 знаку. «КБЖУ семьи за день» — отдельное раскрытие с семейными totals; стоимость дня = полная стоимость ингредиентов семьи, с этой подписью |
| D-06 | Manual target отсутствует | «Ручная цель КБЖУ не задана»; только actual numbers, без denominator/progress/нулевой нормы/оценки выполнения. Не добавлять медицинские средние |
| D-06 | Manual target задана | Метрика «{actual} из {target} {unit}», источник «Цель введена вручную · на человека в день». Показывать численное отклонение; предупреждать отдельно по каждой метрике только если unrounded actual > target×1,1, при равенстве +10% не предупреждать |
| D-06 | target=0 в Б/Ж/У | При actual=0 показать «0 из 0 г» без процента; при actual>0 «Выше заданного значения 0 г» с предупреждением. Не делить на ноль; target не становится отсутствующим |
| D-07/17 | Prices / quantities | Деньги half-up до копеек, одни канонические product-row totals на обоих экранах; ингредиенты = запас + покупки. Quantity без скрытого отсечения значимых данных; совместимые units единообразны; не угадывать плотность/массу штуки |
| D-07 | Provenance | На menu/shopping под сводкой «Цены ориентировочные, проверяйте в магазине» и «Оценка цен: {regions} · {pricePeriod}» с фактическими регионом и датой/периодом наблюдения. Раскрытие «Источники расчёта» показывает настоящие source/record IDs, reference quantities/units, catalog version. При нескольких регионах/периодах перечислить их, не изображать единый источник |

КБЖУ — расчёт запланированных блюд, не дневник съеденного. Подпись «КБЖУ рассчитаны по составу продуктов и не являются медицинской рекомендацией». Без фото/графика/календаря истории Phase 2: у неё нет нового media element с отдельными fake loading/error. Допустимый новый план содержит каждый ожидаемый слот; отсутствие recipe instance = неполные данные и ошибка целостности, не кнопка «Добавить» Phase 4.

### Базовые shopping и pantry coverage

| Decision | Predicate / данные | Представление |
|----------|-------------------|---------------|
| D-19 | Есть active plan | h1 «Список покупок»; тот же период/семья; «{N товаров} · ≈ {purchase} ₽» и те же три стоимости. N — только ненулевые purchase rows, без покрытых запасами строк и без количества recipe occurrences |
| D-12/19 | Purchase rows | Разделы по порядку овощи и фрукты → мясо и рыба → молочное → бакалея → хлеб → прочее; пустые разделы не выводить. Внутри одна строка на productId+compatible basis: название, «Купить {missing}», оценочная цена; при частичном покрытии «Нужно {required} · Из запасов {covered}» |
| D-19 | Источники строки | Native details «Из {N блюд}»; число означает recipe instances, не уникальные recipeIds. Внутри дата, тип слота, название и вклад количества каждого instance, в том числе повторяющегося рецепта; одинаковое название не объединяет разные IDs |
| D-12/19 | Covered quantity >0 | В конце свёрнутый details «Уже есть дома · ≈ {coveredValue} ₽», строки показывают покрытые количества/стоимость; partial продукт присутствует здесь и своей недостающей частью в purchases, без двойного вычета |
| D-12 | Unknown quantity / incompatible basis | Ни скидки, ни fake 0: отдельная поясняющая строка «{product}: количество не указано — запас не вычтен» либо «{product}: единицы запаса и потребности несовместимы — запас не вычтен». Известный запас с нулевым покрытием не входит в covered-value |
| D-12 | Все количества покрыты | N=0, покупка 0 ₽, сообщение «Всё необходимое уже есть дома»; это не «Всё куплено». Список покрытых количеств остаётся доступен |
| D-19 | Возврат | «К меню» как Link; суммы получаются из того же active ID/snapshot. Никаких checkbox/progress «куплено», редактируемого quantity, фильтров, share/export/add до соответствующих фаз |

Числа — только из валидированных derived calculations; значения `{…}` в контракте — параметры, не синтетические факты. «Из запасов» означает количественное покрытие снимком, не физическое списание и не обещание подтверждённой безопасности продукта. На шаге ограничений уточнить «Без рыбы — исключаем также морепродукты»; выбранные пять ограничений, аллергии и явные IDs не ослабляются ради результата, отсутствие safety metadata не обозначается check/«подходит».

| TIMEOUT | «Не получилось составить меню»; «Подбор занял больше 30 секунд. Повторите попытку или измените настройки»; те же две кнопки |
| BUDGET_TOO_LOW proven | «Для {peopleLabel} с выбранными ограничениями бюджета недостаточно» ({peopleLabel}: «1 человека», «2 человек» и т. д.) + реальный период и список условий; «Изменить бюджет» → шаг 2. | Search exhausted / no proof | «Не удалось подобрать меню за отведённый поиск. Это не доказывает, что подходящего меню нет»; «Повторить» / «Изменить настройки»; цену найденного кандидата не называть минимумом |
| NO_RECIPES_FOUND proven | «В доступном каталоге нет блюд для выбранных условий»; «Проверьте время готовки и ограничения. Мы не будем снимать их автоматически»; «Изменить настройки» / «Повторить» |
