# Requirements: MealPlan

**Defined:** 2026-10-25
**Core Value:** получить допустимое меню с прозрачным бюджетом и согласованные покупки с количественным учётом запасов.

Источники: [PRD](../reference/PRD.md), [OPEN_QUESTIONS](../reference/OPEN_QUESTIONS.md), [PROJECT](PROJECT.md). v1 равен всему P0, включая дополнения F §12.1. Исследование уточняет риски и способы реализации, но не повышает P1/P2 и не разрешает C/Q. Все пункты ниже ещё не реализованы и не проверены.

## v1 Requirements

### Гостевой старт и навигация

- [ ] **APP-01**: Пользователь работает без регистрации и открывает P0-маршруты `/`, `/plan/new`, `/plan/generating`, `/menu`, `/recipe/:id`, `/shopping`, `/pantry` (PRD P0-01).
- [ ] **APP-02**: Пользователь видит на телефоне нижнюю навигацию и «Новое меню», от 1200 px — боковую; мастер и генерация полноэкранные (P0-01; поведение вкладки профиля до P1 — C-06).
- [ ] **APP-03**: Пользователь видит приветствие с «Как это работает» и переходом в мастер, а при существующем меню попадает на `/menu` (P0-02).
- [ ] **APP-04**: Пользователь запускает «Меню за 1 клик» с последними настройками или подтверждёнными дефолтами: 2 человека, 3 000 ₽, 7 дней, без ограничений, до 30 минут; неутверждённые дефолты не выдаются за заданные (P0-02; Q-02).

### Четырёхшаговый мастер

- [ ] **WIZ-01**: Пользователь проходит четыре шага с прогрессом, возвратом и закреплённым действием; выход с первого шага при введённых данных подтверждается (P0-03).
- [ ] **WIZ-02**: Пользователь не теряет введённые параметры при переходах между шагами и перезагрузке (P0-03).
- [x] **WIZ-03**: Пользователь выбирает 1–10 человек и цель поддержания/похудения/набора; шаг 1 содержит выбор 1–7 дней с дефолтом 7 (P0-04; C-02, Q-01/02).
- [ ] **WIZ-04**: Пользователь задаёт бюджет числовым полем от 500 ₽ и синхронным слайдером 1 000–15 000 ₽ с шагом 100 и видит расчёт на человека в день по согласованной базе периода (P0-04; Q-01/02).
- [ ] **WIZ-05**: Пользователь выбирает время до 15/30/60 минут или любое и разнообразие same/medium/max (P0-04; Q-06).
- [ ] **WIZ-06**: Пользователь включает ограничения без рыбы/глютена/лактозы, вегетарианство, халяль и добавляет/удаляет теги «Не люблю» с автоподсказкой (P0-04).
- [ ] **WIZ-07**: Пользователь добавляет домашние продукты через поиск или популярные чипы, необязательное количество/единицу и флаг «Скоро испортится» (P0-04,13; Q-07).
- [ ] **WIZ-08**: Пользователь может пропустить шаги 3/4 и запустить генерацию; сохранённые ограничения и запасы обрабатываются по явно согласованной политике пропуска (P0-03–04; Q-11).
- [ ] **WIZ-09**: Пользователь задаёт целевую норму КБЖУ и видит её происхождение; мини-форма расчёта/средние нормы реализуются только после разрешения C-04/Q-03, без выдуманных значений (P0-04; спорная граница калькулятора P1 сохранена).

### Достоверные данные и единая модель

- [ ] **DATA-01**: Пользователь получает расчёты по продуктам со стабильными ID, явной базой цены/нутриентов и рецептам с определённым исходным выходом (P0-08,10–11; Q-05/14).
- [ ] **DATA-02**: Пользователь не получает нулевую цену/КБЖУ или отметку пищевой безопасности вместо неизвестных данных; неполнота данных явно обрабатывается (P0-05,08; Q-14).
- [ ] **DATA-03**: Пользователь может пройти сценарий через локальные mock-адаптеры с реальными доменными вычислениями, без платного API/LLM/обязательного Firebase (P0-01,05,15).
- [ ] **DATA-04**: Пользователь получает согласованные данные всех экранов из одной доменной модели; внешние и сохранённые данные валидируются, сбой сохранения не маскируется успехом (P0-15–16; Q-15).

### Количества, питание и бюджет

- [ ] **CALC-01**: Пользователь получает корректную сумму совместимых количеств: 1 кг + 500 г = 1500 г, 1 л = 1000 мл; неподтверждённые г↔мл/шт не смешиваются (P0-11).
- [ ] **CALC-02**: Пользователь меняет масштаб рецепта от исходных порций, без двойного умножения; количества, общие КБЖУ и цены изменяются согласованно (P0-10,15; Q-05/16).
- [ ] **CALC-03**: Пользователь видит Ккал/Б/Ж/У из структурированных ингредиентов для порции, блюда, дня и среднего по фактическому периоду с явным масштабом на человека/семью (P0-08; Q-03/04).
- [ ] **CALC-04**: Пользователь видит отдельно полную стоимость ингредиентов, оценку дополнительных покупок и стоимость покрытия запасами (P0-08,11).
- [ ] **CALC-05**: Пользователь видит остаток и превышение относительно согласованной базы лимита; генерация не превышает жёсткий бюджет молча (P0-08; Q-01/04/08).
- [ ] **CALC-06**: Пользователь получает недостающие количества после агрегации всего плана и однократного вычета запасов: 500 г − 200 г = 300 г, результат неотрицательный (P0-11,13).
- [ ] **CALC-07**: Пользователь видит одинаковые округлённые показатели на связанных экранах и в экспорте по документированным единым правилам (P0-08,15; Q-16).

### Генерация и варианты

- [ ] **GEN-01**: Пользователь получает меню выбранного периода с учётом людей, бюджета, нормы, времени, ограничений, запасов и разнообразия, вычисленное воспроизводимым алгоритмом (P0-04–05).
- [ ] **GEN-02**: Пользователь не получает рецепты, нарушающие аллергию/явные исключения; неизвестная безопасность не считается подтверждённой (P0-05).
- [ ] **GEN-03**: Пользователь видит загрузку с меняющимися строками, может отменить генерацию и вернуться; отменённый/устаревший ответ не заменяет актуальное состояние (P0-05).
- [ ] **GEN-04**: Пользователь получает понятную ошибку, повтор и возврат к сохранённым настройкам при таймауте 30 секунд или неуспехе (P0-05).
- [ ] **GEN-05**: При BUDGET_TOO_LOW пользователь может перейти на шаг бюджета; минимальная сумма показывается только при обоснованном расчёте, отсутствие рецептов не маскируется успехом (P0-05; Q-08).
- [ ] **GEN-06**: Пользователь получает предусмотренные 3–4 варианта и выбирает активный; недостаток допустимых вариантов обрабатывается по явной политике, без фиктивных отличий (P0-06; Q-06).
- [ ] **GEN-07**: Пользователь пересобирает меню с теми же настройками, сохраняя предыдущий вариант для сравнения; пересоздание с потерей данных подтверждается (P0-06; Q-06).
- [ ] **GEN-08**: Пользователь запускает подбор из остатков, где скоро портящиеся продукты при возможности получают приоритет первых 1–2 дней без нарушения жёстких ограничений (P0-13).

### Просмотр меню

- [ ] **MENU-01**: Пользователь видит даты периода, бюджет с остатком, средние ккал относительно нормы и ориентировочный характер цен (P0-07–08).
- [ ] **MENU-02**: Пользователь переключает «Текущий день / Вся неделя» на телефоне и дни с выделением сегодняшнего; на десктопе видит сетку четырёх типов приёмов (P0-07; Q-01).
- [ ] **MENU-03**: Пользователь видит фото 4:3, название, текстовый цветной бейдж типа приёма, время, ккал, цену порции и использование запасов; карточка открывает рецепт (P0-07,10).
- [ ] **MENU-04**: Пользователь видит сводку дня Ккал/Б/Ж/У и стоимость, предупреждение при превышении нормы более 10% выражено также текстом (P0-08).
- [ ] **MENU-05**: Пользователь переходит к настройкам, повторному составлению и экспорту через действия меню и к покупкам через закреплённую кнопку со счётчиком (P0-07).

### Изменение блюд и рецепт

- [ ] **MEAL-01**: Пользователь выбирает замену в bottom sheet из 3–5 подходящих альтернатив с дельтой цены/ккал; недостаток вариантов явно обработан (P0-09; Q-08).
- [ ] **MEAL-02**: Пользователь убирает блюдо и добавляет подходящее в пустой слот через «+ Добавить блюдо» (P0-09).
- [ ] **MEAL-03**: После замены/удаления/добавления/смены порций пользователь сразу получает согласованные итоги активного плана и покупки; ошибка подтверждения не оставляет ложный успех (P0-15).
- [ ] **REC-01**: Пользователь открывает рецепт с фото, временем, ценой порции, ингредиентами с ценами и отметками запасов и нумерованными шагами (P0-10).
- [ ] **REC-02**: Пользователь видит четыре КБЖУ на порцию и раскрывает вклад каждого ингредиента (P0-10).
- [ ] **REC-03**: Пользователь применяет ×0,5/×1/×2 к нужному вхождению рецепта, видит пересчёт и может открыть замену из рецепта (P0-10,15; Q-05).
- [ ] **REC-04**: При неизвестном ID пользователь видит «Такого рецепта нет» и может вернуться к меню (P0-10,16).

### Продукты дома

- [ ] **HOME-01**: Пользователь в `/pantry` находит и добавляет продукт, редактирует количество, отмечает «Скоро испортится» и удаляет запись (P0-13).
- [ ] **HOME-02**: Пользователь видит реальное количественное покрытие потребности запасами; неизвестное количество обрабатывается явно и не считается бесконечным (P0-11,13; Q-07).
- [ ] **HOME-03**: При изменении запасов пользователь получает актуальные покупки/стоимость и согласованное действие пересчёта меню; C-03 разрешён и не допускает незаметно устаревших данных (P0-15; C-03).

### Список покупок

- [ ] **SHOP-01**: Пользователь получает агрегированный список недостающего по ID и совместимым единицам для активного варианта, с раскрытием «из N блюд» (P0-11).
- [ ] **SHOP-02**: Пользователь сворачивает группы по отделам и фильтрует список табами категорий с иконками (P0-12; Q-12).
- [ ] **SHOP-03**: Пользователь отмечает купленное: строка зачёркнута и уходит вниз группы, общий/групповой прогресс отражает отметки (P0-12).
- [ ] **SHOP-04**: Пользователь видит в свёрнутом блоке «Уже есть дома» покрытые количества и их оценочную стоимость (P0-11–12).
- [ ] **SHOP-05**: Пользователь добавляет ручную позицию с названием/количеством/отделом, меняет количество и удаляет строку; политика последующего пересчёта явная (P0-12; Q-09).
- [ ] **SHOP-06**: Пользователь сбрасывает отметки и скрывает купленное через «Показать только нужное» (P0-12).
- [ ] **SHOP-07**: Пользователь передаёт текст списка через Web Share либо копирует его при отсутствии поддержки; сбой действия виден (P0-12).
- [ ] **SHOP-08**: Пользователь видит количество товаров/оценку суммы, пустое состояние без меню и состояние «всё куплено» с переходом к новому меню (P0-12,16).

### PDF

- [ ] **PDF-01**: Пользователь открывает модалку PDF с живым превью и опциями группировки, цен, количества, пустых чекбоксов (P0-14).
- [ ] **PDF-02**: Пользователь скачивает фактический PDF A4 portrait с датой, конфигурируемым логотипом, суммой, категориями/иконками и чекбоксами (P0-14; Q-13).
- [ ] **PDF-03**: Пользователь получает читаемый русский многостраничный PDF без разрыва строки товара, после загрузки используемых шрифтов/изображений (P0-14).
- [ ] **PDF-04**: Пользователь получает файл по выбранным опциям из того же актуального снимка, что и превью; состав и дата файла определены явно (P0-14–15; Q-13).
- [ ] **PDF-05**: Во время экспорта пользователь видит загрузку, а при ошибке — «Не удалось создать файл. Повторить» вместо фиктивного скачивания (P0-14,16).

### Качество сквозного сценария

- [ ] **UX-01**: Пользователь получает русский UI, ₽ и единицы г/кг/мл/л/шт с единым форматированием и конфигурируемым брендом (P0-16).
- [ ] **UX-02**: Пользователь видит применимые loading/empty/error с понятным действием и может подтвердить либо отменить потерю данных, включая тост отмены 5 секунд там, где он выбран (P0-16).
- [ ] **UX-03**: Пользователь работает на 360/390/430/768/1280 px без горизонтального скролла страницы/перекрытий; управление доступно клавиатурой, фокус виден, контраст AA, цели ≥44×44 px, основные кнопки ≥48 px (P0-16).
- [ ] **UX-04**: Пользователь получает проверенный сквозной P0: расчётные Vitest, реальные браузерные Playwright-сценарии, typecheck, ESLint, production build и просмотр скачанного PDF; ограничения проверки браузеров и LCP указаны честно (P0-16; Q-17).

## v2 Requirements

Отложенный P1, не входит в текущий roadmap и не начинается до приёмки всего P0:

- **NEXT-01**: PNG 1080×1920 с предпросмотром, обрезкой длинного списка и передачей файла.
- **NEXT-02**: Полноэкранная готовка, таймеры, звук/вибрация, Wake Lock при поддержке, отметка приготовленного.
- **NEXT-03**: Профиль, персональная норма, предпочтения, параметры по умолчанию; граница калькулятора мастера остаётся C-04.
- **NEXT-04**: Избранные рецепты/недели, история, повтор недели, календарь; статистика экономии сохраняет P2.
- **NEXT-05**: График калорий и дополнительные нутриенты при наличии проверенных данных.
- **NEXT-06**: Email/пароль, регистрация, сброс, Google/Firebase Auth и перенос гостевых данных.
- **NEXT-07**: Готовые планы команды и скрываемый на 7 дней баннер профиля.
- **NEXT-08**: «Можно приготовить» по проценту совпадения и добавление своего продукта с КБЖУ.
- **NEXT-09**: `/recipes`, поиск/фильтры/популярное и степпер порций на карточке меню.

## Out of Scope

| Feature | Reason |
|---------|--------|
| Семья, разные предпочтения, общий realtime-список | P2, только отдельный запрос |
| Экономия за период, талисман, drag-and-drop | P2; текущие остаток бюджета/покрытие запасами остаются P0 |
| Собственные рецепты, сохранённые приёмы, штрихкоды | P2 |
| Доставка, магазины/акции, КБЖУ по фото, партнёрские планы | Исключены F |
| Обязательная регистрация, платные LLM/API/облака | Гостевой MVP, ограничения стоимости A |
| Выдуманные нормы, цены, рецептурные данные и гарантированный минимум бюджета | Противоречат A/D |

## Acceptance Criteria

Полная приёмка — AC-01–AC-18 в PRD §14. Здесь каждое требование должно получить ровно одну фазу-владельца; сквозная проверка UX-04 повторно проверяет интеграцию, не меняя владельцев реализации. Пункты с C/Q остаются в v1: наличие вопроса не является разрешением удалить функцию.

## Definition of Done

Реализовано требуемое поведение, выполнены релевантные автоматические проверки и пользовательский путь, проходят TypeScript/ESLint/build, отсутствуют известные блокирующие регрессии, документация обновлена. Для фактических данных подтверждены источники, единицы и порции; нерешённые критические вопросы зависимой функции не скрыты. Выполненная и невыполненная проверка различаются в отчёте.

## Decision Gates

- До реализации денежных/пищевых формул: Q-01/03/04/05/07/14/16 и C-04 в зависимом объёме.
- До генерации/вариантов: Q-06/08, правила времени/разнообразия/недостатка кандидатов.
- До применения настроек/запасов: Q-02/11/15, C-03/C-06.
- До ручных покупок/категорий: Q-09/12; до PDF: Q-13; до итогового QA: Q-17.
- Q-10/18 в части неподтверждённого автосписания и P1/P2 не расширяют P0.

Реестр остаётся в reference/OPEN_QUESTIONS.md. Планирование может предлагать решения с основанием; нельзя отмечать их как подтверждённые исходниками без соответствующего доказательства.
