# MealPlan

Русский гостевой интерфейс планирования питания. Локальная разработка не требует аккаунтов, ключей или платных API.

## Локальный запуск и проверки

Команды выполняются в корне проекта с установленными и подтверждёнными зависимостями:

```text
npm run dev -- --host 127.0.0.1
npm run test:unit -- --run
npm run test:e2e -- e2e/storage.spec.ts --project=chromium
npm run test:e2e -- e2e/storage.spec.ts --project=chromium --grep exit
npm run typecheck
npm run lint
npm run build
```

Playwright сам запускает Vite на порту 4173; порт должен быть свободен. Полный `npm run test:e2e` использует Chromium, Firefox и WebKit; браузеры должны быть установлены. Современный WebKit не подтверждает совместимость именно с Safari 15. Сборка `dist/` нацелена на Safari 15.

## Сохранение черновика

Ключ `mealplan:guest:draft:v1` содержит `{ schemaVersion: 1, draft }`. До чтения запись запрещена. Сохраняются текущий шаг 1–4 и исходные незавершённые строки; это не применение настроек и не изменение глобальных запасов.

Повреждённая запись и неизвестная версия остаются неизменными до явного подтверждения «Сбросить черновик». Сброс затрагивает только этот ключ. При ошибке чтения или записи можно продолжить в памяти; «Повторить сохранение» пишет последние изменения. Успех показывается после успешной записи. Пока запись не завершена, диалог выхода честно сообщает об отсутствии сохранения. Подтверждение выхода не удаляет черновик; возврат сохраняет текущий ввод в памяти.

Синхронизация между вкладками не гарантируется: каждая вкладка редактирует свой снимок в памяти, а последнее успешное сохранение определяет запись для следующей загрузки. Предупреждения о конфликтах и слияние вкладок пока не входят в контракт. Данные в памяти теряются после закрытия/перезагрузки страницы, если запись не удалась.

## Текущие границы

Планы 01-01–01-03: гостевые маршруты, навигация, восстановление и безопасный выход, основа переходов 1–4 с валидацией. Поля следующих шагов расширяются планами 01-04–01-06. Генерация, готовое меню, покупки и глобальные запасы ещё не реализованы; экран их отсутствия не сообщает об успехе. P1 и P2 не включены в этот срез.

Калькулятор нормы заблокирован решением C-04/Q-03 в плане 01-07. Ручная норма не заменяет это решение. Проверка записи:

```text
node scripts/verify-calculator-decision.mjs docs/decisions/nutrition-calculator.json
```

Валидатор проверяет полноту контракта, не выбирает формулу, не подтверждает медицинские факты и не удостоверяет подлинность ответа человека. Отсутствующая, неподтверждённая и неполная запись возвращает ненулевой код. `scope-amendment` всегда возвращает `REPLAN_REQUIRED` и не разрешает реализацию по старому плану.

Схема для будущего фактического решения `keep-p0`:

- `decision`, `status: human-confirmed`, `humanConfirmedAt` (ISO), `humanResponse: { text, source }` с дословным ответом и ссылкой на его происхождение; `scopeReferences` и `sourceReferences` — непустые списки строк; `formulaVersion`.
- `inputContract`: `sex`, `age`, `height`, `weight`, `activity`; каждый содержит `unit`, `admissibility`, `default` (явный `null` допустим), `absence`.
- Непустые объекты `coefficients`, `rounding`, `resultContract`, `errors`; заполненные `useSemantics`, `absencePolicy`.
- `uiStates`: явные описания `empty`, `loading`, `error`, `partial`. Для синхронного локального расчёта нельзя изобретать загрузку.
- `independentExamples`: минимум два объекта `{ input, expected, provenance }` с разными входами, разными конечными численными ожидаемыми результатами и независимым происхождением. Синтетические fixtures тестируют только валидатор, не служат основанием формулы.

Для переноса объёма дополнительно нужны `amendmentReferences` и отдельное согласованное перепланирование. До этого WIZ-09 и вся фаза не объявляются завершёнными.
