# Фаза 2 — независимая оценка Windows WebKit

Дата: 29.10.2026. Оценку выполнил оркестратор отдельно от исполнителя release-проверок.

## Контрольный эксперимент

На новой странице без MealPlan, React, стилей или обработчиков размещены две обычные ссылки между двумя кнопками. Один и тот же Playwright-скрипт запускает установленные Chromium156.0.8078.4, Firefox157.0 и WebKit27.2 с соответствующими Desktop devices. Начальный фокус устанавливается только на первую кнопку; затем выполняются настоящие события клавиатуры.

Исходный скрипт: `.tmp/02-10-independent-native-links.mjs`; фактический JSON: `.tmp/02-10-independent-native-links.json`. Выполнен успешно, exit0.

| Движок | Фактическая последовательность обычного Tab |
|---|---|
| Chromium | Первая ссылка → Вторая ссылка → последняя кнопка |
| Firefox | Первая ссылка → Вторая ссылка → последняя кнопка |
| Windows WebKit | Последняя кнопка → BODY с document.hasFocus=false → первая кнопка; ссылки пропускаются |

Alt+Tab в этом Windows WebKit также пропускает обе ссылки. Это не подтверждённый обход ограничения. Никакие системные настройки, tabIndex приложения или CSS не изменялись. Программная установка фокуса на ссылку не использовалась как доказательство клавиатурного обхода.

## Вывод и границы

Пропуск нативных ссылок воспроизведён независимо от приложения. Поэтому два неуспешных sequential linkTab-теста локального Windows WebKit не доказывают дефект MealPlan. Реальные последовательные Tab/ShiftTab/Enter-сценарии MealPlan подтверждены Chromium и Firefox. Проверка End отдельно подтверждает доступность нижнего содержимого без ослабления геометрических условий.

**Два теста WebKit остаются failed в исходных отчётах, а их требование для реального Safari — manual/unverified.** Нет утверждения, что WebKit240/240 прошёл, что Safari на macOS/iOS проверен или что пользователь выполнил ручную приёмку. Общее покрытие Windows WebKit:238passed/2failed из240. Исторический Safari15, реальные устройства и экранный диктор также не проверены этой диагностикой.

## Решение оркестратора

Технический checkpoint типа human-verify (Gate:blocking, не blocking-human) разрешён по действующему auto-mode только в части продолжения независимых проверок и передачи двух случаев в ручную приёмку. Это автоматическое техническое решение оркестратора, **не ответ пользователя и не ручной pass**. Основание: `execute-phase.md`, раздел `checkpoint_handling`, и приведённый независимый эксперимент.

Приёмка фазы и переход к следующей фазе этим решением не разрешаются автоматически. Все оставшиеся human-check перечисляются в отчёте независимого верификатора и UAT. Числа исходных неуспешных запусков сохраняются. Новых продуктовых требований или исключений для поддерживаемого Safari не вводится.
