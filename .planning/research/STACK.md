# Исследование технологического стека — MealPlan

**Область:** русскоязычная мобильная SPA для детерминированного планирования питания, запасов и покупок.
**Дата исследования:** 2026-10-25.
**Уверенность:** MEDIUM — значение получено через `gsd-tools query classify-confidence --provider context7 --verified`. Документация сопоставлена с официальными страницами релизов; совместная установка и сборка ещё не выполнялись.
**Статус:** рекомендации для roadmap; код приложения и зависимости этим исследованием не устанавливались.

## Требования и принятые рекомендации

Обязательные ограничения задают [PROJECT.md](../PROJECT.md), [PRD.md](../../reference/PRD.md), [OPEN_QUESTIONS.md](../../reference/OPEN_QUESTIONS.md), [AGENTS.md](../../AGENTS.md) и [mealplan-domain](../../.agents/skills/mealplan-domain/SKILL.md). Предпочтительный стек уже выбран: React, strict TypeScript, Vite, Tailwind CSS и React Router. Vitest, Playwright, ESLint, проверка типов и production build входят в критерии готовности. Гостевой режим, чистая доменная логика, mock API и бесплатная локальная работа обязательны; Firebase, TanStack Query и Zustand не являются автоматически обязательными.

**Рекомендация исследования:** небольшая клиентская SPA, один Zustand-store для согласованных исходных данных, версионированное сохранение в localStorage через отдельный адаптер, каталог продуктов/рецептов в локальных валидируемых файлах, асинхронный mock API, чистые TypeScript-расчёты. PDF — отдельный лениво загружаемый модуль. Сервер, база данных и учётная запись не нужны для первого сквозного P0.

Выбор библиотек не закрывает вопросы Q-03–Q-16: формулу нормы, смысл бюджета, базовые порции, накопление вариантов, неизвестные запасы, ручные правки, состав PDF и достоверные данные необходимо определить до приёмки соответствующих функций. В исследовании нет новых значений КБЖУ, цен или медицинских коэффициентов.

### Данные, расчёты и хранение

| Средство | Версия | Назначение | Правило применения |
|---|---|---|---|
| Чистый TypeScript | Тот же TS `6.0.3` | КБЖУ, порции, единицы, агрегация, pantry, бюджет и генерация | Одна реализация вычислений вне React; UI и PDF получают одинаковую расчётную модель. Случайность генерации — только воспроизводимая, если она потребуется |
| Локальные JSON/TS fixtures + runtime validation | Встроенные средства | Начальные 10–15 mock-рецептов и дальнейший каталог | Проверять ID, размерности, базовые порции, числовые значения, происхождение нутриентов/цен и полноту ограничений. TypeScript не валидирует загруженный JSON. Схемную библиотеку добавлять только при росте повторяющихся проверок |
| localStorage + Zustand persist | Web API + Zustand `5.0.16` | Гостевой черновик, pantry, планы и правки | Только небольшой сериализуемый снимок исходных данных, `schemaVersion`, `catalogVersion`, migration и обработка ошибок. Не сохранять фото/base64/PDF, функции, Promise и AbortController [S8, S9] |
| Repository/API adapter | Собственный интерфейс, без дополнительной библиотеки | Сменяемый источник каталога/планов | Асинхронные операции с реальной доменной логикой; типизированные ошибки, отмена и защита от устаревшего ответа. Mock не должен возвращать фиктивный успех |
| Intl.NumberFormat / Intl.DateTimeFormat | Browser API | Русские числа, RUB и даты | Общие форматтеры; форматирование отделено от вычислений. Правила округления Q-16 сначала фиксируются явно |

Рекомендую хранить исходные параметры, вхождения рецептов/порции, активный вариант, pantry и пользовательские правки, а стоимость/нутриенты/необходимые покупки получать селекторами из одного доменного расчёта. Не сохранять независимые итоги каждого экрана как разные источники истины. Политика сохранения правок/чекбоксов при пересчёте остаётся Q-09, срок хранения и предел числа вариантов — Q-06/Q-15.

localStorage синхронный; записи должны быть небольшими. Чтение/JSON parse/запись могут завершиться ошибкой. Нужны проверка снимка до гидратации, миграция, понятное уведомление о невозможности сохранения и сохранение текущей рабочей сессии в памяти. Нельзя автоматически очищать весь origin или молча считать повреждённые сохранённые аллергии отсутствующими. Резервный снимок и восстановление — рекомендуемые меры, не новые требования продукта. Хранилище браузера не является гарантированной резервной копией и не даёт синхронизацию устройств [S8, S9].

Для P0 не устанавливать IndexedDB-обёртку. Если появятся большие история/изображения/транзакции, заменить StorageAdapter на IndexedDB, сохранив границы репозитория. Это условное развитие, не расширение P0.

### Экспорт и вспомогательные зависимости

| Средство | Проверенная версия | Назначение | Решение |
|---|---|---|---|
| jsPDF | `4.2.1` | Создание/скачивание A4 PDF | Сохранить технологию подробного ТЗ; загружать при открытии экспорта. Не выбирать старый jsPDF 2.x по устаревшему примеру: релиз 4.2.1 содержит исправления безопасности [S10] |
| html2canvas | `1.4.1` | Рендер отдельного экспортного шаблона | Требуется F/PRD; использовать простую проверенную вёрстку, собственные ресурсы, ожидание шрифтов/изображений и рендер страниц по отдельности [S11] |
| CSS variables + локальные шрифты | Без нового runtime-пакета | Токены UI, одинаковый шрифт в экспорте, кириллица | Конкретный финальный шрифт Q-17 не утверждён. Проверить лицензию и наличие русских глифов; PNG/иконки/SVG из разрешённых локальных ресурсов |
| Нативные формы и небольшие общие компоненты | React/CSS | Поля, степперы, карточки и ошибки | Не добавлять целую UI/form-библиотеку до появления конкретной необходимости. Доступность модалок и bottom sheet должна проверяться независимо от выбора библиотеки |

**PDF требует отдельной реализации пагинации.** Наивный снимок всей длинной страницы и нарезка изображения могут разорвать товар и упереться в ограничения canvas. Рекомендация: построить экспортную модель из того же расчётного снимка, разложить строки в A4 без деления строки, затем рендерить каждую страницу и добавлять через `addPage`. Превью использует ту же модель/пагинацию. Скрытый шаблон должен иметь вычисляемые размеры, например располагаться вне видимой области; `display:none` не подходит для измерения. Ограничения CSS/CORS/canvas у html2canvas задокументированы [S11].

Кириллица в HTML→canvas зависит от фактически загруженного шрифта; при растровом экспорте PDF содержит изображение, а не автоматически доступный/выделяемый текст. Если используются `doc.text` или векторные текстовые элементы, встроенные PDF-шрифты недостаточны: требуется локальный TTF с нужными глифами и регистрация через `addFileToVFS/addFont`. Это разные пути, их нельзя смешивать в предположениях [S10]. Возможность выделять текст не заявлена как новое требование P0.

Собственные изображения предпочтительнее удалённых URL: `useCORS: true` не исправляет отсутствие CORS-разрешения на стороне источника. Ошибку генерации/отсутствующие ресурсы нельзя подменять успешным пустым скачиванием. Большой экспорт, кириллица, переносы и совпадение опций с превью — ранний технический spike, а не последняя косметическая задача [S11].

Playwright WebKit — тестовая сборка WebKit, а не установленный Apple Safari. Она не подтверждает совместимость именно с iOS Safari 15. Мобильная эмуляция и ширина 390 px также не превращают Chromium в iPhone. Отдельная проверка на соответствующем Safari остаётся ограничением QA, пока такого окружения нет; не объявлять её выполненной [S13].

Обязательные ворота разработки: реально выполнить unit/E2E в относящейся к изменению области, typecheck, ESLint и production build. Для PDF нужен факт скачивания и визуальное открытие многостраничного результата; одно существование кнопки или Blob не доказывает читаемость. В данном исследовании тесты приложения не запускались: приложения пока нет.

## Установка при исполнении первой фазы

Ниже ориентир для последующей реализации, **не выполненные команды**. Предварительно проверить engines/peers и доступность нужных releases; инструменты lint подобрать согласованно с TS 6.0.3. После установки зафиксировать lockfile и проверить дерево зависимостей.

```bash
# Основные runtime-пакеты
npm install --save-exact react@19.3.1 react-dom@19.3.1 react-router@8.5.0 zustand@5.0.16

# Экспорт — отдельный ленивый модуль приложения
npm install --save-exact jspdf@4.2.1 html2canvas@1.4.1

# Сборка и проверки
npm install -D --save-exact vite@8.3.5 @vitejs/plugin-react@6.1.2 typescript@6.0.3 vitest@5.0.5 @playwright/test@1.64.1
npm install -D tailwindcss@3.4.17 postcss@8 autoprefixer@10 @types/react@19 @types/react-dom@19 @types/node@24

# Совместимые ESLint/typescript-eslint/hooks/refresh версии добавляются после проверки peer dependencies.
# После локальной установки @playwright/test скачать нужные браузеры:
npx playwright install chromium firefox webkit
```

Не запускать scaffold поверх пользовательских документов с перезаписью каталога. Структура исходников добавляется в существующий репозиторий; reference/ и .planning/ сохраняются. Стек не требует Docker, глобальной установки инструментов, платного облака или публикации.

## Рассмотренные альтернативы

| Рекомендуется | Альтернатива | Когда альтернатива оправдана |
|---|---|---|
| Vite SPA | Next.js / SSR framework | Когда появится подтверждённая потребность в публичных SEO-страницах/серверном рендеринге. Сейчас добавляет второй архитектурный выбор без пользы для гостевого P0 |
| Zustand для общих исходных данных | React Context + useReducer | Допустимо для очень малого объёма состояния; здесь меню, pantry, покупки и варианты имеют много общих изменений. Это инженерный выбор, не требование исходников |
| localStorage adapter | IndexedDB | Когда измеренный объём/частота записей или транзакции перестают подходить localStorage; не по гипотетическому миллиону пользователей |
| Локальный async API adapter | MSW | Когда понадобятся настоящие HTTP-контракты и сетевые сценарии разных клиентов. Для локальной реализации собственный адаптер достаточен |
| Чистые вычисления и ограниченный поиск | Оптимизационный solver / WASM | После определения ограничений и профилирования простого алгоритма на целевом каталоге. Не подключать тяжёлый solver, пока неизвестны веса критериев и семантика бюджета |
| jsPDF + html2canvas по ТЗ | Прямой векторный PDF / browser print | Если spike покажет неприемлемое качество/память, зафиксировать отклонение от технологии ТЗ; оценить векторный рендер через тот же ExportModel. `window.print()` не заменяет предусмотренные превью и скачивание автоматически |

## Что не подключать в P0

| Не подключать сейчас | Причина | Что использовать |
|---|---|---|
| Платные LLM/API, nutrition API с ключом как обязательную зависимость | Запрет стоимости без разрешения, детерминированность, достоверность данных | Собственные проверяемые данные и чистые расчёты; происхождение каталога — Q-14 |
| Firebase Auth/Firestore, сервер и SQL | Для гостевого P0 не требуются; конфигурации нет, авторизация P1 | Локальные репозитории и сменяемый API adapter |
| TanStack Query заранее | Пока отсутствует отдельный удалённый источник server state; риск двух источников истины | Zustand + адаптер; добавить Query при реальном backend и отделить кэш ответов от пользовательского состояния |
| Tailwind 4 по умолчанию | Не выполняет документированный минимум Safari 15+ | Tailwind 3.4.17 |
| UI-kit, требующий Tailwind 4, целый графический/анимационный набор | Несовместимость браузеров и ненужная зависимость от будущего P1/P2 | Небольшие общие компоненты и токены |
| Redux Toolkit, Immer, form-library, decimal/units/date library без обоснования | Для текущего объёма пока не выявлена необходимость | Простые типы/функции. Если согласованная точность Q-16 потребует decimal, выбрать её отдельно и тестировать |
| PWA/service worker по умолчанию | Полное offline-приложение не заявлено; добавляет жизненный цикл кэша/обновлений | Обычная SPA с локальными данными; не обещать запуск без сети после закрытия вкладки |

## Варианты развития и влияние на roadmap

1. **Основа:** зафиксировать совместимые версии, Safari 15 target, единые токены и минимальный набор проверок. Отдельно обеспечить требуемый ESLint вместо автоматического oxlint из современного шаблона.
2. **Данные и домен:** получить проверенные fixtures, определить расчётные базы и округление, реализовать pure functions и runtime validation. Выбор стека не устраняет блокер достоверных данных Q-14.
3. **Гостевой сквозной поток:** единое состояние, persist/migrations и mock adapter. Проверить перезагрузку, повреждение/недоступность storage и согласованность экранов. Политики Q-06/Q-09/Q-15 зафиксировать явно.
4. **Экспорт:** провести ранний spike длинного PDF на мобильном размере; затем внедрять экспорт из общей модели. Не откладывать исследование canvas/пагинации до финальной приёмки.
5. **Если расчёт блокирует UI:** перенести существующий генератор за тем же интерфейсом в Web Worker. Проверить отмену/таймаут и игнорирование устаревшего результата. Worker — средство отзывчивости, не отдельная библиотека/новое требование.
6. **Если появится backend/P1:** заменить репозиторий, ввести server-state cache при необходимости, отдельно спроектировать перенос гостевых данных. Не добавлять такую инфраструктуру до соответствующего scope.

Уверенность рекомендаций — MEDIUM: официальные возможности проверены; конкретная совместная установка, браузер Safari 15, качество PDF и производительность генератора требуют доказательств на фазах исполнения. Это явно выделенные проверки, а не заявления об уже работающем приложении.
