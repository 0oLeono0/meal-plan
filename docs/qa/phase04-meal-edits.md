# Проверка редактирования меню

Проверка выполнена 20 ноября 2026 года в локальном окружении Windows. Каждый браузер использовал отдельный профиль Playwright. Сквозные сценарии проходят через настоящий мастер, активное меню, связанный рецепт, покупки и сохранение гостя. Отказ записи и изменение из другой вкладки управляются тестовыми условиями с проверкой фактических байтов сохранения.

## Адаптивность и клавиатура

На реальном меню из 82 рецептов на семь дней проверены размеры 360, 390, 430, 768 и 1280 px. Тест открыл меню действий и панель клавиатурой, проверил переходы Tab и Shift+Tab, Escape, возврат фокуса и выбор последней строки. После выбора фокус вернулся к изменённой карточке. Переход к покупкам подтвердил итоговый бюджет и появление источника из выбранного блюда. При запуске подбора проверено сообщение об ожидании.

На 1280 px скриншот и браузерный тест зафиксировали потерю 240 px ширины диалога из-за отступа боковой навигации. RED `85d1b7a` подтвердил 320 вместо 560 px. В `71f8737` диалог занимает 560 px по центру, а заголовок и кнопка закрытия остаются видимыми при прокрутке списка. Целевой Chromium прошёл 2/2, включая повтор без смены продукта. Итоговые снимки `.tmp/phase04-05/screenshots/alternatives-{360,768,1280}.png` просмотрены. Снимки длинного имени и большой дельты используют отдельный синтетический набор, явно доверенный только тестом.

Эквивалент изменения раскладки при масштабе 200% проверен на эффективной ширине 640 px вместо 1280 px. Также использовано окно 360 × 420 px. В обоих случаях текст и дельты доступны с прокруткой, кнопка закрытия остаётся видимой, горизонтального переполнения нет. Это проверка изменения раскладки при уменьшении эффективной ширины. Системное увеличение текста, фактический переключатель масштаба в интерфейсе браузера и дикторы не запускались.

Замер открытия списка из 82 рецептов для сохранённого плана на семь дней дал 248 мс в одном целевом запуске Chromium при 390 × 460 px. Замер включает действие с клавиатуры и ожидание первой полной выдачи в тесте. Это локальный замер, скорость на телефонах не измерялась. Точное время каждого прогона хранится в JUnit.

Первый полный WebKit выполнил 14/15. После реального клика множитель выбрался и сохранился, но клавиатурный фокус остался на заголовке. Отчёт `.tmp/phase04-05/final-webkit.xml` и трасса сохранены. Коммит `ce989bc` явно фокусирует выбранную кнопку при применении порций. Тот же WebKit-сценарий прошёл в отдельном повторе (`webkit-portion-focus-green.xml`).

## Прогоны браузеров

Команда для каждого движка — `npm run test:e2e -- e2e/meal-edits.spec.ts --project=<движок> --workers=1`. Время приведено по JUnit без округления до минут. Отчёты хранятся в `.tmp/phase04-05`.

| Движок | Полный прогон | Время | Отчёт |
| --- | --- | --- | --- |
| Chromium | 15/15 | 104,14 с | `final-chromium.xml` |
| Firefox | 15/15 | 157,26 с | `final-firefox.xml` |
| WebKit | 15/15 после исправления фокуса | 170,06 с | `after-focus-webkit.xml` |

На `ce989bc` целевой повтор обоих сценариев порций дополнительно прошёл 2/2 в Chromium (21,24 с) и 2/2 в Firefox (30,17 с). Ни один обязательный сценарий этих прогонов не пропущен. Замеры открытия панели в полных прогонах составили 242 мс в Chromium, 381 мс в Firefox и 421 мс в WebKit. Реальные устройства, нативный Safari 15 и системные средства доступности требуют отдельных наблюдений. Исторические случаи нативного Tab в Windows WebKit из фаз 2 и 3 остаются зарегистрированы отдельно.

## Автоматические проверки

Полный `npm run test:unit -- --run` прошёл 611/611 в 23 файлах за 216,43 с после завершения браузерных прогонов. Журнал — `.tmp/phase04-05/final-unit.log`.

`npm run typecheck`, `npm run lint` и `npm run build` завершились с кодом 0. Журналы `.tmp/phase04-05/final-{typecheck,lint,build}.log`. Vite сохранил известное предупреждение о размере чанка. Основной JS — 771,41 кБ, gzip — 198,02 кБ.

Регрессии связанных адресов, отмены и конкурирующей записи покрыты фазовыми E2E. Пять выпусков сохранений и набор из 12 вариантов прошли в полном Vitest. Дополнительный отдельный запуск прежних E2E не включён в этот отчёт.

## Покрытие требований

| Требование | Что проверено |
| --- | --- |
| MEAL-01 | Панель предлагает 0, 1 или до 5 подходящих замен, вычисляет дельту покупок за период и калорий за приём, ограничивает список совместимыми блюдами. Escape сохраняет байты и возвращает фокус. |
| MEAL-02 | Удаление оставляет пустой слот после перезагрузки. Добавление использует новый идентификатор в том же месте. Полностью пустое меню сохраняет все места, закупка показывает ноль товаров. |
| MEAL-03 | Меню, рецепт и покупки используют одну проекцию. Отказ записи возвращает подтверждённые значения, повтор сохраняет правку, при конфликте байты другой вкладки остаются. Поздний ответ не меняет посещённый маршрут. |
| CALC-02 | Множитель вычисляется от исходного числа семейных порций. ×2 → ×0,5 → ×1 меняет одно вхождение, расчёт на порцию остаётся прежним, бюджетный отказ не пишет данные. |
| REC-03 | В связанном рецепте доступны порции и замена. Выбранные порции сохраняются при замене, переход на новый рецепт подтверждается сохранением. Прямой и устаревший адрес не дают изменить блюдо. |

Независимые числовые ожидания в `src/domain/mealEdits.test.ts` подтверждают закупку 225 ₽ после замены против 300 ₽ до неё с учётом общего запаса. Ровно 500 ₽ допустимы, 500,001 ₽ превышают точный лимит. Для добавления в пустой слот контрольная дельта — 50 ₽ и 50 ккал. Проверки адаптера и контроллера используют пять выпусков (52/56/68/75/82 рецептов), сохранение пустых мест и предел 12 вариантов. Сверка Git подтвердила совпадение исходных файлов каталога, рецептов, справочных данных и иллюстраций с точкой начала фазы `0b1f62a`.

## Пользовательская приёмка

В меню откройте замены у одного блюда и выберите подходящий вариант по цене покупок и калориям. Откройте этот рецепт, измените число порций и посмотрите покупки. Затем уберите блюдо из меню и верните блюдо в освободившееся место. Оцените, понятны ли подписи и результат каждого действия.
